# 探索：路演 demo 套件与数字人讲解员（探索稿 v0.1）

扩展方向，不影响路演视频 skill 的进度。这里先把方向写清楚，并列出路演视频 skill 现在就该留好的接口。

## 一、设想

把“做路演”整个过程做成一套 skill，路演视频是其中一个子 skill：

| 子 skill | 做什么 | 现状 |
|---|---|---|
| 路演 demo 制作 | 从客户需求到可演示的产品：需求梳理、落地推演、做出演示版、部署上线 | 还没有，靠手工按项目做 |
| 路演视频 | 用真实 demo 做演示片 | 正在做 |
| 数字人讲解员 | 把 demo 以公网方式交给客户，客户和数字人对话，了解功能、看操作、留下需求 | 本稿探索 |

三者共用同一套底子：

- 客户背调与文风画像
- 品牌视觉
- 功能清单（功能、操作路径、实现状态）
- 数字人资产（形象、音色、口型配置、授权记录）

## 二、数字人讲解员能做什么

客户拿到一个链接（带口令），打开后是 demo 本身加一位讲解员：

1. **问功能**：“你们能不能按部门统计？”讲解员按功能清单回答：已实现、演示版、还在规划，不夸大。
2. **看怎么操作**：“这个怎么用？”有三种给法，由浅到深：
   - 播放路演视频里对应的那一段。视频的时间索引里记着每段、每句对应哪个功能，直接跳过去。
   - 讲解员一边讲，一边在 demo 上高亮要点的按钮，让客户自己点。
   - 讲解员替客户操作一遍，客户看着界面动。
3. **留需求**：
   - 客户说出自己的需求，讲解员追问几句，整理成结构化的需求条目：谁、在什么场景、要什么、现在怎么做。
   - 需求条目推送给我们，可以走飞书、邮件或后台。
   - 同时在对话里复述给客户确认。
4. **语音**：
   - 第一步是语音输入：按住说话，识别成文字。
   - 第二步是全双工：客户随时插话、打断，讲解员边听边说。

## 三、技术选型

### 形象

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 预渲染片段 | 预先生成待机、说话等几段循环视频，按状态切换；回答的语音另行合成，口型粗略匹配 | 便宜，不需要服务端显卡；做过类似的切分装配 | 口型对不上具体内容，只适合短回答 |
| 实时口型驱动（开源） | LiveTalking、Open Avatar Chat 一类，服务端用 MuseTalk 等模型实时驱动，WebRTC 推流 | 自主可控，数据不出去 | 要服务端显卡；LiveTalking 要求成片带它的水印；Open Avatar Chat 实测平均响应约 2.2 秒 |
| 实时数字人服务（商用） | HeyGen LiveAvatar、Tavus 等，WebRTC 推流，自带打断与语音检测 | 效果最好，Tavus 自称端到端延迟不到 600 毫秒，支持全双工 | 按分钟收费；国内访问与数据合规要核实 |

国内的实时数字人服务这次没查到具体资料，下一轮调研补上，重点看火山引擎。

### 语音

| 阶段 | 做法 |
|---|---|
| 半双工 | 语音识别，加大模型回答，加语音合成（豆包语音合成 2.0，和路演视频同一个音色） |
| 全双工 | 端到端实时语音模型。字节 2026 年 4 月发布了全双工语音大模型 Seeduplex，用在豆包通话里；开源方向有 NVIDIA 基于 Moshi 的 PersonaPlex 等 |

我们已经有火山引擎的账号与语音识别、语音合成的使用经验，从豆包这条线往全双工走最顺。

### 知识与边界

讲解员只回答四类材料里有的：

- 功能清单
- 路演旁白稿
- 产品文档
- 用户另外给的资料

不知道的就说不知道，并引导客户留下需求。

讲价格、合同、交付周期这类问题，统一回答“这部分请和我们的同事沟通”，并把问题记进需求条目。

### 部署

- 套在 demo 外面的一层页面，带口令门禁。
- 对话记录与需求条目存在我们自己的后台。
- 客户的语音默认不长期保存。

## 四、风险

- **承诺越界**：讲解员说了没实现的功能。所以功能清单的实现状态是硬约束，回答前必须查清单。
- **对外标识**：讲解员是直接和客户对话的 AI，页面上要写明“AI 讲解员”，让对方知道在和 AI 说话。这一点和路演视频默认不加标识不同。
- **形象授权**：用真人形象要本人授权，和路演视频里的讲解员是同一份授权记录。
- **成本**：实时数字人与全双工语音按时长计费，要设单次会话上限。
- **隐私**：客户的语音与需求属于客户信息，存储与访问要有记录。

## 五、路演视频 skill 现在就留好的接口

这几件成本很低，已经写进问题库和 SKILL.md：

1. **数字人资产统一存档**：`~/.config/roadshow-video/avatars/<名称>/`，存形象素材、授权记录、音色、口型配置。路演视频里的讲解员和以后的 demo 讲解员用同一份。
2. **功能清单**：推演时顺带记下每个功能的名称、操作路径、实现状态，写进 `roadshow/功能清单.json`。旁白提到的功能必须在清单里。
3. **时间索引**：每次交付都出 `out/索引.json`，记每段、每句的起止时刻与对应功能，讲解员以后可以按功能跳到视频里对应的那一段。

## 六、下一步

路演视频 skill 做完以后再展开：

1. 补调研：国内实时数字人服务（火山引擎等），以及 Seeduplex 的接入方式与价格。
2. 拿一个已有的 demo 做最小原型：半双工语音，加预渲染形象，加功能清单问答，加需求留言。
3. 原型跑通再决定要不要上实时口型和全双工。
4. 路演 demo 制作 skill 单独立项，先把你现在做 demo 的流程整理出来。
