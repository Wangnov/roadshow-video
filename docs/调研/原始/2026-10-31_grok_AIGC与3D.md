# 代码生成视频 × AIGC × 3D：产品路演片工作流调研

调研日期：2026-10-31  
时间窗：优先 2025-01 至 2026-10，帖子实际集中在 2026-01 至 2026-10-31  
方法：以 X 关键词检索、语义检索和线程展开为主。网页只用来核对 Remotion `colorKey`、`@remotion/three`、HyperFrames、video-shotcraft README，以及 OpenMontage 绿幕管线讨论。  
范围说明：病毒清单帖里的 GitHub star、镜头卡数量经常和仓库 README 不一致。下面凡是写到数量，能核对的以仓库说明为准，核对不到的标明「帖子自称」。模型名（Opus 5.5、Seedance 2.5、Kling Avatar 2 等）按发帖人原文记录。

对「真实产品界面 + 运镜」最有用的共识先写在这里：界面、图表、字幕、logo 用代码渲染；人物、氛围、材质用短 AIGC 镜头；3D 只负责机身、相机和灯光。所有层锁在同一条帧时钟上，改一镜只重渲这一镜。

**Lucas Magliari（@l_magliari）**

## 二、网页补充（不是 X 帖，用来把做法钉死）

这些页面在 2026-10 仍能对上上面的帖子，用来补「具体怎么对齐、怎么抠」。

**Remotion 绿幕**  
`colorKey()` 在 `@remotion/effects`（检索到的版本文案是 v4.0.472）。用在 `<Video>` 一类画布组件上，把接近键控色的像素变透明。默认键控色 `#00ff00`，`similarity` 默认 0.18，`smoothness` 默认 0.08，另有 `spillSuppression` 处理绿溢色。官方绿幕文档要求 WebGL2。  
含义：AI 生成的绿幕人物可以直接作为 Remotion 图层，不必先在外部剪辑软件抠完。溢色和边缘仍要调 similarity 和 smoothness，头发发糊时再换下一节的 AI 遮罩。

**帧精确的素材**  
`<OffthreadVideo>` 在渲染时用 FFmpeg 抽出精确那一帧，避免 HTML5 video 在无头渲染里丢帧、循环错位。带 alpha 的素材（ProRes 4444、带 alpha 的 VP9）要走透明通道提取，帧会变成 PNG，更慢，只对需要透明的镜头开启。进工程前把素材规范成 H.264、`yuv420p`、恒定帧率，能少掉一类解码失败。

**3D 和屏幕贴图**  
`@remotion/three` 的 `<ThreeCanvas>` 包住 React Three Fiber，动画必须来自 `useCurrentFrame()`。官方说明：R3F 的 `useFrame()` 跟 Remotion 的逐帧渲染不是同一时钟，用了会闪、会抖。`useVideoTexture()` / `useOffthreadVideoTexture()` 把一段视频贴成纹理。官方 starter 就是一部 3D 手机，屏幕里放视频，可改颜色、尺寸、厚度、圆角。`<Sequence>` 放进画布时要 `layout="none"`。  
含义：路演片的标准镜头是「Blender 或程序化手机 + 真实录屏当屏幕纹理 + 帧号驱动相机」。

**OpenMontage 绿幕管线（2026-04 的 GitHub 讨论）**  
流程是：直方图判断绿或蓝，先用 FFmpeg chromakey，质量不够再落到 rembg（U2Net）。讨论里写的阈值是色键质量低于 80% 就换 AI 分割。合成预设有主播（人物约 65% 靠下）、全幅背景、画中画、左右对半。后面再烧 Remotion 字幕。  
含义：色键是快路径，AI 抠像是失败回退。不均匀灯光、衣服上的绿色、皮肤溢色都会让纯 ffmpeg 失败。

**HyperFrames**  
HeyGen 开源，Apache-2.0。视频是 HTML，时间写在 `data-start`、`data-duration`、`data-track-index`。动画适配 GSAP、CSS、Lottie、Three.js、Anime.js。技能用 `npx skills add heygen-com/hyperframes` 或 Claude Code 插件安装，也覆盖 Codex、Cursor。媒体技能可以接 HeyGen 的数字人、配音和生成视频。和 Remotion 的差别是页面技术：HTML 对 agent 更熟，React 组件对已有产品代码更熟。

**video-shotcraft README**  
对 Claude Code 和 Codex 说「给我的产品做宣传片」。agent 抓真实页面，从配方卡里选镜头，Remotion 动画，卡点，音效，逐帧检查。交付包括 MP4、可改的 Remotion 工程、浏览器里的 Motion Workbench，以及剪映草稿。2.5D 页面相机写在组件里，用归一化进度 `t` 驱动。

## 三、总结

### 常见做法

一条能反复渲染的路演片，帖子里反复出现的分工是：

1. 人先批一份短文档：`BRIEF.md` 或一条 JSON。里面有镜头表、每镜秒数、画幅、字体、颜色、哪一句必须念到、哪些素材允许商用。
2. 真实界面单独采集。网页用 Playwright 截图或录一段操作。桌面端用 HyperFrames Computer Use 点真 App 再重建 HTML。截图也可以拆成 Remotion 组件，但那是「可改的复刻」，像素以录屏为准。
3. 带字的一切走代码。界面、图表、字幕、logo、价格、按钮状态用 Remotion、HyperFrames/GSAP 或 Manim。文生视频不负责这些像素。
4. AIGC 只做短素材。可灵、即梦 Seedance、Veo、Hailuo、Runway、Pika 出 2 到 5 秒氛围、人物或材质。先有关键帧或参考图，再图生视频。口型交给 Kling Avatar、HeyGen 这类数字人，或者放弃对口型、改成旁白。
5. 需要「人站在界面旁」时，生成绿幕或纯色背景，再用 Remotion `colorKey` 或 ffmpeg chromakey 叠上去。边缘不干净就换 BiRefNet、SAM 2、MatAnyone、rembg，导出带 alpha 的中间片。
6. 3D 负责机身和相机。Blender MCP 建模型，导出 GLB，React Three Fiber 放进 `@remotion/three`。屏幕用 `useOffthreadVideoTexture()` 贴真实界面。动画全部从帧号计算。`useFrame()` 留在交互网站，不进成片。
7. 时间对齐以声音为王。旁白按句生成、固定 seed。Whisper 或 Soniox 给出词的起点。字幕、手势、音效峰值、硬切都落在这些起点上。3D 相机和 GSAP 用同一个 `t`。
8. 渲染要能重来。先 3 张静帧，再低分辨率草稿，再母版。中间帧用 PNG。改一镜只重跑那一镜，配音和已通过的 AIGC 素材留在缓存里。多比例从同一时间轴重排。响度常见目标是人声 -14 LUFS。
9. Agent 的角色是编排和改代码。Claude Code、Codex 写分镜、调用 skill、看抽帧、改坏帧。花费型 API（Veo、Kling、即梦）要人点头再跑。

2.5D 视差是轻量替代：把界面按前景、面板、背景拆层，用帧号做轻微位移和缩放。帖子里认为它到不了绕机身一周的深度，适合开场 2 秒，不适合主演示。

### 反复出现的坑

- 风格不一致。AIGC 镜头的光色、颗粒和代码 UI 的平光对不上。有效做法是 AIGC 极短、运动极小，代码层统一调色和颗粒，而不是让每段视频模型自由发挥。
- UI 幻觉。Seedance、即梦、可灵、Sora 画出来的按钮会糊、会乱码、点下去的状态对不上真产品。中文圈已经把这当成默认失败，所以界面改采集或重写。
- 抠像毛边和绿溢色。纯色键吃光照。衣服、屏幕、皮肤上的绿会穿帮。先色键，质量不够再 AI 遮罩。遮罩要膨胀再模糊，硬边比毛边更假。
- 闪烁。逐帧抠图没有时间记忆，头发会跳。视频 matting（MatAnyone 一类）是为这个存在的。3D 里用 `useFrame()` 也会闪，因为渲染不是实时播放。
- 对口型失败。通用视频模型让角色说话，嘴和音轨对不上。要么数字人专模，要么旁白。
- 确定性被中途压缩破坏。默认 JPEG、重复编码、可变帧率、全范围 YUV，都会让「同一帧号」在不同次渲染里变样。规范成恒定帧率、yuv420p，审查帧用 PNG。
- 第 1 帧闪一下。GSAP 的 from 状态立刻生效，元素没有预先 `opacity: 0`。路演片开头最容易露馅。
- 版式回归。改一句文案会把旁边的组件挤乱。代码可编辑不等于改完仍对。要静帧 diff。
- 版权和授权。音乐、音效、字体、档案照片、模型权重各自一份许可证。BiRefNet 能换掉演示站里的非商业抠图，就是因为这一步会翻车。Wikimedia 公有领域和 CC0 被写进提示词，是因为事后再清更贵。数字人脸和克隆声音还有肖像权，帖子里用的是生成角色或自己的声音流程，不能直接套到真人客户。
- 一次生成整片。长提示让 agent 写完所有镜头，容易报错并烧掉额度。按镜分批，坏了只重做那一镜。
- 算力。Blender 设备加逐帧渲染会卡成掉帧。预览和母版分开。
- 语言。视频模型直接说中文或日语，语调不稳。旁白独立合成更稳。
- 清单帖失真。2026-10 的转发链里，star 数、配方数量、模型代际会越传越大。选型以仓库 README 和一次本地短片为准。

### 针对「真实产品界面 + 运镜」的一条可执行顺序

1. Playwright 或 Computer Use 抓真实流程，每个关键状态一张 PNG，加一段 15 到 30 秒操作录屏。
2. 写 6 到 10 镜的 `BRIEF.md`。主演示只保留一个用户动作。
3. 界面镜头用 Remotion 或 HyperFrames 做 2.5D 推拉、光标、标注。录屏原画作为像素来源。
4. 需要手机或笔记本出镜时，用官方 3D 手机模板或 Blender 导出的 GLB，屏幕纹理贴第 1 步的录屏，相机只由帧号插值。
5. 若要人物，单独生成绿幕或纯背景短镜头，Remotion `colorKey` 叠到界面层。头发失败再跑 MatAnyone 或 BiRefNet，不要整段重抽。
6. 旁白独立生成，词级时间戳驱动字幕和音效。人声 -14 LUFS。
7. 三张静帧通过后渲草稿，FFprobe 看分辨率、帧率、时长，再出母版。需要剪映的话导出 alpha 或草稿，而不是把界面再压进一个生成模型。
