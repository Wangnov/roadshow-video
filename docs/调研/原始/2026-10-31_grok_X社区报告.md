## 社区总结

### 最常见的做法

1. **视频当代码编译，不当生成模型抽卡。** 2025 年中到 2026 年 10 月，主流路径是 Remotion / HyperFrames / HTML+GSAP，用 Claude Code、Codex 或 Cursor 写画面。生成式视频（Veo、MiniMax H3、Seedance）只负责隐喻镜头或开场，产品界面本身用代码或真实录屏。
2. **先写分镜和时间数字，再渲染。** 高赞实践都会要求：场景表、每场时长、旁白词、运镜动词。渲染前先出静帧或 Studio 预览，人口头过。
3. **真实产品有两条采集路。**
   - 代码内复用：在仓库里直接引用 React 组件（Josh Pigford 路线），界面 100% 真，但要维护一套“演示用”状态。
   - 浏览器内操作：Playwright / Chrome DevTools MCP / product-demo 插件真正点击产品，再叠加运镜（Wang Shuyi、Manoj、video-shotcraft 路线）。更适合路演。
4. **旁白、字幕、音效拆开做。** 旁白用 ElevenLabs（质量）、Kokoro / Piper / Chatterbox / edge-tts（本地免费）。字幕用 Whisper / WhisperX / Soniox / faster-whisper 的逐字时间戳，而不是按场景估。点击、whoosh、成功音单独生成，卡在词起点。
5. **把风格写成 Skill。** 官方 `remotion-dev/skills` 只管框架。真正出片靠第二层：video-shotcraft 的镜头配方、chaojifeng 的声画事件模型、vawe 的 easing 表、或自己从参考片提炼的 `my-video-style/SKILL.md`。
6. **渲染后自检。** 抽每秒一张 contact sheet、OCR 对旁白、检查首帧黑屏、文字出画、音量 LUFS。同一会话既做片又打分会放水，要用新会话看静帧。

对“真实产品界面操作加运镜做路演视频”，社区里最接近的流水线是：

```
产品仓库 / 已登录测试环境
  → Claude 写脚本（hook → 3~5 个真实操作 → CTA），等人确认
  → Playwright 或 Chrome MCP 按旁白节奏点击、输入、等待
  → 录干净操作轨（或逐帧截 HTML/产品界面）
  → Remotion / video-shotcraft / OpenScreen 加推镜、光标、切点、字幕
  → ElevenLabs 或本地 TTS 分段配音，Whisper 对齐
  → FFmpeg 混音（人声 -14 LUFS，BGM 低 9~17 LU）
  → 抽帧质检 → 改一刀 → 终渲 1080p/1440p
```

### 被反复提到的坑

| 坑 | 谁在说 | 对策 |
|---|---|---|
| agent 不停 zoom，运镜停不下来 | Cagatay；chaojifeng 明确禁止全程匀速推镜 | 每次点击只推一次，写死回弹和 hold；参考片分析 zoom 时机 |
| TTS 无法按场景时长一次说完 | Josh Pigford | 每句/每场单独出音频，再对齐 |
| 口型对不上 | Mauricio（Veo 角色） | 路演改画外旁白；口播才需要口型 |
| 第一版几乎都不好看 | Vishi、vandit、Josh 来回改了 1 小时 | 强制分镜审批；第三版再接近 |
| 同一会话既做片又质检会放水 | vandit：36 次里 18 次空过检查 | 全尺寸静帧 + 新会话 critique |
| Remotion 默认 JPEG 发糊 | moatez / Condz 的高端剪辑 prompt | `--image-format=png` |
| Playwright JPEG 是 full range，QuickTime 拒播 | Otto | `scale=in_range=full:out_range=tv` |

| HyperFrames 有人测 15 秒 brief 渲 23.5 分钟 | Manoj 评 awesome-claude-video-skills | 短片先用纯 Claude + Remotion；量产 HTML 片再上 HyperFrames |
| Remotion 超过 3 人团队要公司许可 | 多条评测重复 | 个人/小团队可用；更大团队评估 HyperFrames（Apache 2.0）或 HTML+Playwright |

### 最受欢迎的工具与 Skill

**渲染引擎（按出现频率）**

1. **Remotion + 官方 Agent Skills**（`npx skills add remotion-dev/skills`）  
   2025 年 7 月社区账号点名，2026 年 1 月 Josh 出爆款案例，之后几乎所有教程的默认引擎。官方 skill 覆盖 create / markup / captions / studio / render，文档写明同时服务 Claude Code、Codex、Cursor。安装量在 marketplace 上以十万计。
2. **HyperFrames**（HeyGen 开源，Apache 2.0）  
   2026 年下半年崛起：HTML 即时间线，无头 Chrome 逐帧 + FFmpeg。技能包同时打 Claude Code / Codex / Cursor。适合量产、可重复的 explainer；有人反馈短片比 Remotion 慢。
3. **HTML + GSAP + Playwright 逐帧截屏**  
   Otto、Genzoh、vandit 的路线。agent 最会写 HTML，盲测里甚至优于专用 JSON 视频格式。路演可以把真实 UI 嵌进同一页。
4. **Manim**  
   官方早期推荐，适合公式和概念，不适合产品界面。

## 对“真实产品界面 + 运镜路演片”的直接建议

1. 主链路用 **Playwright 或 Chrome MCP 操作真实产品**，不要用生成模型“画一个假 UI”。
2. 装两层 skill：底层 **`remotion-dev/skills`**，上层 **`video-shotcraft`**（镜头语言）或自建 `my-video-style`。
3. 运镜写成禁令和配额：每次操作最多一次 push-in，必须 hold，禁止连续 zoom；参考 Cagatay 的翻车和 chaojifeng 的三层声画模型。
4. 旁白分段生成、逐字对齐、人声 -14 LUFS；界面点击音卡在动词上。
5. 渲染前批分镜，渲染后用新会话看静帧；价格、功能名、版本号全部配置化，改一句重渲，不要重拍。
6. 模板做成 changelog / 发版流水线，主路演片和每周更新片分开：主片讲故事，更新片 20 秒换数据。
