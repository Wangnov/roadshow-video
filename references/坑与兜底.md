# 坑与兜底

渲染、配音、配乐、素材、协作里踩过的坑。每条写现象、原因、做法。

- 遇到问题先按现象在这里查。
- 新踩的坑在经验回写时按同样格式追加，不写客户名、人名、项目细节。
- 标“已进引擎”的条目，模板里已经处理，正常不会再遇到；改引擎时别把兜底删掉。

## 一、画面与渲染

### 渲染越慢，页面里的时间跑得越快
- **现象**：页面里的轮播变快，定时出现的内容和旁白对不上，多进程分段的接缝处画面跳变。
- **原因**：Playwright 装好假时钟后，默认仍按真实时间继续走。渲染一帧耗时越长，页面里流逝的时间越多。
- **做法**：页面加载完立即暂停时钟，之后只靠逐帧推进。有自己计时器或轮询的段落，用单进程渲染。（已进引擎）

### 画面和点击位置错开
- **现象**：光标点在按钮上，实际点中的是旁边的元素；或者画面整体往下错了一截。
- **原因**：应用里的 `scrollIntoView` 会连带滚动导演页外层容器。
- **做法**：每帧把导演页窗口的滚动归零。（已进引擎）

### 镜头运动中的点击偏一帧
- **现象**：推镜过程中点击，落点和光标差一点。
- **原因**：点击坐标按上一帧的镜头位置换算。
- **做法**：点击前先把镜头摆到当前帧再算坐标。（已进引擎）

### 界面一闪而过，或开场透底
- **现象**：切页瞬间露出空白页、加载中状态或上一页残影；片头前几帧露出底下的界面。
- **原因**：切页后没等页面就绪就出画；章节卡没有遮住首帧。
- **做法**：切页后等就绪信号（关键元素出现、字体加载完、网络空闲）再出画；章节卡与片头卡从第 0 帧开始遮盖。（已进引擎）

### 聚焦框圈了个空
- **现象**：聚焦框或标注落在空白处。
- **原因**：目标元素还没渲染、被折叠，或选择器匹配到了隐藏元素。
- **做法**：聚焦与标注前先校验目标存在、可见、尺寸不为零，不满足就报警告并停下。（已进引擎）

### 点了按钮没反应
- **现象**：画面上点击了，界面没有变化。常见于非按钮元素绑定的点击事件、手机端页面的触摸事件。
- **原因**：iframe 里的合成点击没有触发应用的事件处理。
- **做法**：点击时同时用脚本触发一次，写法 `tap(目标, { js: true })`。点击后核对界面是否进入预期状态，没有就报警告。

### 点击落空：按钮被挤走了
- **现象**：打字之后紧接着点按钮，没点中。
- **原因**：输入框随文字自动变高，按钮往下移了。
- **做法**：等打字结束、布局稳定后再点；关键按钮加脚本点击兜底。

### 持续的黑色闪屏
- **现象**：某一段里断断续续出现整屏发黑的帧。
- **原因**：无头 Chromium 的显存预算不够，GPU 合成时丢帧。
- **做法**：启动参数加 `--force-gpu-mem-available-mb=8192`；问题段改成单进程依次渲染，不和别的段抢 GPU。

### 成片在部分播放器里发灰或打不开
- **现象**：成片在 QuickTime、投影电脑或某些会场播放器里整体发灰、对比度变低，或者干脆拒播。
- **原因**：浏览器截图是全范围色彩（0 到 255），直接编码进视频时没有转成视频标准范围（16 到 235），也没写色彩参数。
- **做法**：编码时加 `scale=in_range=full:out_range=tv`，并写明 `-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv`。交付前在 QuickTime 和一个 Windows 播放器里各打开一次。

### 截帧发糊
- **现象**：界面上的小字、细线边缘发虚，放大后有色块。
- **原因**：截帧用了默认质量的 JPEG。
- **做法**：截帧用 PNG，或质量不低于 95 的 JPEG；配合 2 倍超采样再缩回成片分辨率。

### 渲染期间界面突然重载
- **现象**：渲染到一半，画面回到初始状态。
- **原因**：产品开着开发服务器的热更新，渲染期间有人改了产品文件。
- **做法**：渲染开始后不改产品文件；需要改就停下渲染，改完从头重渲该段。

### 页面弹出“模型接口不可用”的提示
- **现象**：画面里出现降级提示，或结果和录制时不一样。
- **原因**：渲染时没起模型接口，或接口返回不稳定。
- **做法**：检查阶段录一次回放缓存，正式渲染全部走缓存；缓存缺失时停下报错，不让页面降级出画。

### 页面里的音视频不出声或报错
- **现象**：产品里嵌的音频在渲染浏览器里播不了。
- **原因**：Playwright 自带的 Chromium 不支持 AAC 等专利编码。
- **做法**：渲染时把页面里的音频换成同内容的 ogg；成片里的声音另行混入。

### 多进程渲染的接缝
- **现象**：分区间渲染后拼接，接缝处状态不一致。
- **原因**：每个进程从中间开始，应用状态没有重放到那一刻。
- **做法**：每个进程都从第 0 秒重放到自己的区间起点，再开始截图；区间按重放开销分配，越靠后的区间越短。（已进引擎）

### 全片拼接后音画不同步或卡顿
- **现象**：分段各自正常，拼成全片后某处卡顿或音画错位。
- **原因**：各段帧率或时间基不一致。
- **做法**：拼接前统一帧率与时间基；全片编码优先用硬件编码器，速度快很多。

### 字幕在浅色界面上看不清
- **现象**：白色字幕压在白色或浅灰的界面上，几乎看不见；交剪映草稿时，导入的字幕默认是纯白字，问题更明显。
- **原因**：只靠字幕下面的渐变暗带或柔和阴影托底，界面一亮就不够；剪映导入 SRT 默认没有描边。
- **做法**：字幕一律白字黑描边（剪映第一个预设样式），成片里烧的和剪映草稿里的字幕轨用同一个样式。（已进引擎）

### 关键操作看不懂
- **现象**：观众问“这里确认发出的是什么”。
- **原因**：关键操作发生时，画面没有交代操作对象。
- **做法**：确认、发出、提交这类操作之前，先聚焦或标注被操作的内容，旁白点明对象，再点击。

### 生成视频的分辨率不对
- **现象**：图生视频返回的尺寸和帧率与请求不符，比如请求 1080p，拿回 1264×720、24 帧。
- **原因**：服务端自行调整了规格。
- **做法**：生成后先探测真实规格，再统一插帧、放大到成片规格。

## 二、配音

### 句与句之间换了一个人
- **现象**：同一部片子里，每句旁白的声音不太一样。
- **原因**：用文字描述设计音色时，每次调用都会重新设计一个声音。实测句间声纹一致性只有 0.3 到 0.7，预置音色是 0.83 到 0.90。
- **做法**：旁白只用预置音色。

### 音色名写错，声音悄悄变了
- **现象**：指定的音色听起来和音色目录的描述对不上，但接口没有报错。
- **原因**：有的服务遇到不认识的音色名，会退回一个默认声音。
- **做法**：用之前对照服务的官方音色列表校验名称，不在列表里的直接停下报错（见 `服务与工具文档.md`）。

### 数字、单位念乱
- **现象**：“3.5 吨”“1,280”“20%”念错或漏念。
- **原因**：有的模型或移植版本没有文本规范化。
- **做法**：合成前把数字、单位、日期、百分号、英文缩写、文号写成读法，放在 `tts` 字段；字幕仍用 `text`。

### 克隆时把参考音的原文也念了出来
- **现象**：合成结果开头多出参考音频里的那句话。
- **原因**：模型对参考原文有专属格式要求，调用时漏了。
- **做法**：用之前按 `服务与工具文档.md` 的链接读官方文档，照文档写参考原文的格式；踩过的格式要求记进该文档的“踩过的坑”。

### 豆包语音合成返回 45000030
- **现象**：`requested resource not granted`。
- **原因**：账号没开通语音合成，或这把 Key 所属的应用没有授权语音合成。
- **做法**：请用户在豆包语音控制台开通“语音合成大模型”并授权给对应应用。开通后通常几分钟生效，期间每 30 秒重试一次。

### MiniMax 返回 1002
- **现象**：请求被限流。
- **原因**：并发或频率超限。
- **做法**：退避重试，等待时间逐次加长。

### ASR 回听误报
- **现象**：回听显示有错，人耳听是对的，比如“她”识别成“他”。
- **原因**：同音字的识别差异。
- **做法**：按无调拼音比对判断读音，同音字不算错。多音字 ASR 听不出来，`tts` 字段里提前处理。

## 三、配乐

### 每部片子听起来都一样
- **现象**：用户觉得配乐和上一部重复。
- **原因**：一直用同一种风格。
- **做法**：profile 里记下每部用过的风格，下一部换一种。

### 风格显得不正式
- **现象**：爵士、波萨诺瓦这类风格，用户觉得“不够档次、怪”。
- **原因**：这类风格和路演场合不搭。
- **做法**：这类风格不进路演的候选。

### 用模型盲听配乐不可靠
- **现象**：让多模态模型给配乐打分，结论前后矛盾，还会说出并不存在的乐器。
- **原因**：模型对音频细节常有误听，绝对打分不稳定。
- **做法**：需要第二意见时用配对盲测（甲乙随机），比绝对打分可靠。最终以用户试听为准。

## 四、协作与环境

### 用第二台机器渲染
- **做法**：
  - 第二台机器只起产品前端，模型接口全部走回放缓存，所以缓存要先在本机录全。
  - 同步工程时不带密钥文件。
  - 分完段各自渲染，回传分段成片再拼接。

### 用户在流量环境
- **现象**：下载慢，或用户提醒别下大文件。
- **做法**：体检时问不到网络类型，就在第一次要下载超过 500 MB 的东西前问一句；用户说在流量环境，改用云端方案或推迟下载。
