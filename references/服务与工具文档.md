# 服务与工具文档索引

这个 skill **不写适配代码**。各家的模型、接口、参数、音色列表都会更新，甚至调用方式也会改，写死在代码里维护不过来。

每次要用某个服务或工具之前，Agent 按本文的链接**现场读官方文档**，按文档写这一次的调用。本文只记三样东西：

- 精确到章节的官方文档链接。
- 我们实测过的推荐设置，比如音色 ID、语气指令原文、资源 ID。
- 踩过的坑。

**推荐设置和文档冲突时，以文档为准**，并在经验回写时把这里改掉。

链接最后核对日期：2026-10-31，列出的链接当天全部能打开。

## 一、用之前核对四件事

1. 接口地址和鉴权方式没变。
2. 推荐的音色或模型 ID 还在官方列表里。音色名写错时，有的服务不报错，会静默换成别的声音。
3. 要用的参数名、取值范围没变。
4. 错误码的含义没变，尤其是下面记过的那几个。

核对结果写进 `roadshow/体检.json`。发现变化就停下来，按新文档调整，交付后回写本文。

**读文档的方法**

- **MiniMax**：文档页地址加 `.md` 后缀就是 Markdown 原文，总索引在 `llms.txt`，最适合 Agent 读。
- **火山引擎**：文档是网页渲染的，用网页抓取工具读；读不全就用浏览器打开。
- **开源项目**：读 GitHub 的 README 与模型卡。
- 都读不到时，告诉用户卡在哪个链接。不要凭印象写调用。

**实测用法（2026-10-31）**

- **接口**：HTTP 单向流式 V3。
- **请求头**：
  - 新版控制台只要 `X-Api-Key`；旧版控制台用 `X-Api-App-Id` 加 `X-Api-Access-Key`。
  - 2.0 音色的 `X-Api-Resource-Id` 是 `seed-tts-2.0`。2.0 音色只能配 2.0 的资源 ID，1.0 同理。
- **返回**：逐行 JSON，音频是 base64，按顺序拼接；`code` 为 20000000 表示结束。
- **语气指令**：放在 `req_params.additions`（一个 JSON 字符串）里的 `context_texts`。按文档，只取列表第一条，不计费，只对 2.0 音色和声音复刻 2.0 表现力版生效。
- **逐字时刻**：`req_params.audio_params.enable_subtitle` 设为 `true`（注意在 `audio_params` 里，放进 `additions` 不生效）。返回里的 `sentence.words` 是逐字的 `word`、`startTime`、`endTime`、`confidence`，时间单位是秒，从本次请求的音频开头算起，标点跟在前一个字上。每句单独请求时，直接就是 `audio/vo/index.json` 要的 `words`，**用豆包配音不需要另外跑对齐模型**。只对 2.0 音色生效；1.0 音色用 `enable_timestamp`。

**踩过的坑**

- **返回 45000030（requested resource not granted）**：账号没开通语音合成，或这把 Key 所属的应用没授权语音合成。请用户在控制台开通并授权给对应应用；开通后几分钟生效，期间每 30 秒重试一次。
- **2.0 音色 ID 的规律**：都带 `uranus`，以 `_bigtts` 结尾；`ICL_` 开头的是另一类官方音色，以 `_tob` 结尾。用前在音色列表里确认。

### Qwen3-TTS（开源本地），只推荐这一个开源方案

| 内容 | 链接 |
|---|---|
| 官方仓库（模型、预置音色、指令用法、安装） | https://github.com/QwenLM/Qwen3-TTS |

| MLX 版模型卡（举例） | https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-bf16 |

**实测用法（2026-10-31）**

- 1.7B CustomVoice；32 GB 内存用 bf16，16 GB 用 8bit。
- 预置音色用 `serena`（女）、`uncle_fu`（男），两者都需要配 BGM，单独听会显得夸张。
- 语气指令：

  > 用新闻播报的语气，庄重严肃，字正腔圆，不带笑意，语速平稳。

- 速度与内存：见 `问题库.md` 的 Q4.1。

**踩过的坑**

- CustomVoice 模型必须带音色参数，预热那一句也要带。
- 0.6B 量化后错误率明显变差，不用。
- 不用它的文字设计音色做旁白：逐句生成时句与句之间会换人。

## 三、回听与逐字对齐

| 用途 | 内容 | 链接 |
|---|---|---|
| 回听判读音 | Qwen3-ASR | https://github.com/QwenLM/Qwen3-ASR |
| 逐字时刻 | Qwen3-ForcedAligner 0.6B | https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B |
| Apple Silicon 上跑以上两个 | mlx-audio 的语音识别部分；MLX 版对齐模型 | https://github.com/Blaizzy/mlx-audio 、https://huggingface.co/mlx-community/Qwen3-ForcedAligner-0.6B-8bit |
| 其他平台的逐词时间戳 | faster-whisper | https://github.com/SYSTRAN/faster-whisper |
| 云端识别（火山引擎） | 录音文件识别大模型标准版 | https://docs.volcengine.com/docs/doubao-voice/large-model-recording-file-recognition-standard-version-api?lang=zh |

用豆包语音合成 2.0 配音时，合成接口直接返回逐字时刻（见第二节），不用这一节的对齐模型。MiniMax、Qwen3-TTS 或本人录音才需要对齐。用火山引擎的识别做对齐之前，先在文档里确认它返回逐字时间。

**回听结果怎么交给交付检查**

逐句识别后写进片子工程的 `audio/vo/asr.json`，`build/qa.mjs` 读它和原稿比对：

```json
{
  "_model": "Qwen3-ASR-1.7B-8bit（mlx-audio）",
  "a1": { "text": "识别出的整句文字", "audio": "这句音频文件 sha1 的前 16 位" }
}
```

- `audio` 用来判断回听的是不是现在这版配音，重新合成过的句子要重新回听。不写时按文件修改时间判断。
- 实测用的是 mlx-audio 跑 Qwen3-ASR-1.7B 8bit，参数 `language="Chinese"`。
- 比对脚本 `audio/asr_check.py` 要 `pypinyin` 和 `cn2an` 两个 Python 包；装在别的 Python 环境里时，跑检查前用 `PYTHON` 环境变量指过去。

**踩过的坑**

- 回听按无调拼音比对，同音字不算错。阿拉伯数字先统一转成汉字读法再比，“2.0”和“二点零”算一样。
- 多音字 ASR 听不出来，要在 `tts` 读音字段里提前处理。

## 五、剪映草稿

剪映没有公开的草稿格式文档，用开源库生成。不写进本仓库的代码，每次按下面的文档现场写一个小脚本：

| 内容 | 链接 |
|---|---|
| pyJianYingDraft（Apache-2.0），README 的“用法文档”和版本支持表 | https://github.com/GuanYixuan/pyJianYingDraft |
| 完整示例：建草稿、加轨道、视频音频片段、转场、文本 | https://github.com/GuanYixuan/pyJianYingDraft/blob/main/demo.py |
| 新版剪映草稿读不出来时的后备读取器 | https://github.com/GuanYixuan/pyJianYingDraft/releases |

**输入**：片子工程里 `node build/deliver.mjs` 导出的 `out/剪辑清单.json`，时刻按全片算，单位秒：

- `video`：各段画面与在全片里的起点。要先用 `render.mjs --master --nosub` 出不烧字幕的画面，不然剪映里会有两层字幕。
- `audio.vo`、`audio.music`、`audio.sfx`：每段的旁白、配乐、音效三条分轨，已经乘过和成品一样的增益，原样叠加约等于成品。
- `voClips`：逐句的原始配音，只在要换掉某一句时用。
- `subtitles.srt`：全片字幕，直接导入成字幕轨。
- `xfade`：相邻两段重叠的秒数。

**实测做法**（2026-11-01，pyJianYingDraft 0.3.1，Python 3.11，macOS 剪映专业版 11.2，草稿能打开、素材能链接、字幕样式正确）：

- 草稿目录在剪映“全局设置”里的“草稿位置”；macOS 上默认是 `~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft/`。
- **macOS 上素材要复制进草稿文件夹**：剪映 Mac 版读不到草稿目录以外的文件，引用工程里的原路径会弹“链接媒体”、片段显示“暂无访问权限”。先建草稿，把画面和分轨复制到草稿文件夹下的 `media/`（同名文件按段加前缀），再用复制后的路径建片段。
- 库只写 `draft_content.json`，Mac 版剪映自己用的是 `draft_info.json`（保存后会加密）。保存后把 `draft_content.json` 原样复制一份成 `draft_info.json`，实测这样能打开。
- 画面放主轨：主轨上的片段不能重叠，每段两头各让出半个 `xfade`，首尾相接，接缝处给前一段加“叠化”转场，时长取 `xfade`。
- 声音：相邻两段在重叠处要同时响，单数段和双数段分放两条轨，重叠处各自淡入淡出。
- 字幕用 `import_srt` 导入，传一个样式参考片段：白字、居中、黑色描边（`TextBorder` 宽度 40），和剪映第一个预设样式一样，也和成片里烧的字幕一样。不传样式时是纯白字，浅色界面上看不清。
- macOS 上能生成草稿，但不能自动导出成片，导出要用户在剪映里点。

**生成之后**：放进用户的剪映草稿目录前先问一句；用户在剪映里打开核对一次，验收报告里写明剪映版本，没打开过就写进“未验证”。
